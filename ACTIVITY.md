## How to read these numbers

These are **sample success rates**, not time-weighted uptime or an SLA. Checks run every five minutes on the application host. Interruptions between checks can be missed. Host/monitor downtime produces unknown slots, not successful samples. Publication happens daily and after successful deployments; always check the timestamp.

A running container does not prove Discord connectivity or command execution. API health checks process responsiveness, not all integrations. Container recreation resets its start time. These figures are self-reported, not an independent monitoring audit or proof of daily development activity. No January launch date or historical continuous uptime is claimed.
